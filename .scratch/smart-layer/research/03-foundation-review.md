# Foundation review — full reports (ticket 03)

Four parallel read-only reviews, 2026-08-12, each over one slice of the ground the smart
layer sits on. The synthesis lives in the ticket
(`../issues/03-foundation-review.md`); this file is the evidence. Every claim below was
verified by the reviewing agent reading code, not restated from docs. Severities:
**BLOCKER** = the smart layer cannot safely build until fixed · **MAJOR** = must be
planned around explicitly in the architecture ticket (08) · **MINOR** = note, fix
opportunistically.

## Slice 1 — `POST /api/chat` (the weak backend, to be rewritten)

### Sound to build on

- **Auth-first ordering, correctly enforced and correctly documented.** `getRequestUserId` + `unauthorized()` run before body parse and before any DB work (`src/app/api/chat/route.ts:116-117`), with the comment explaining why placement matters. The resolver revalidates via `getUser()` (`src/lib/auth/verifyUser.ts:26`), never `getSession()`, and accepts cookie or Bearer (`src/lib/auth.ts:30-44`). `src/lib/apiAuthBoundary.test.ts` enforces the resolve+refuse pair per handler — but it honestly states (lines 74-76) that it cannot see *ordering*, so that property survives only by hand in a rewrite.
- **The authorization model is coherent for what this route loads.** Transcripts and company documents are shared corpus by founder ruling — migration `20260801_014` (`docs/DATA-MODEL.md:124-132`) grants `SELECT to authenticated USING (true)` on all transcripts — so the `supabaseAdmin` reads in `src/lib/chat/context.ts:28-49` and `src/lib/documents/index.ts:57-78`, gated only by the 401 at the top, are the intended policy, not a leak. Personal data (project context) goes through the **user's** client so RLS decides (`route.ts:187-188`, `src/lib/db/projects.ts:43-57`).
- **The project-context visible-degradation pattern is the template the rewrite should generalize.** Three-state `'ok' | 'truncated' | 'failed'` computed server-side (`route.ts:184-209`), reported on `x-project-context` only when not ok (`route.ts:243-244`), whitelisted on read (`src/lib/api/chat.ts:52-54`), rendered and **persisted** so the warning survives reload (`src/components/chat/ChatView.tsx:206-243`). `buildProjectContext` returns `truncated` + `fullLength` so the UI meter and server enforcement are one function (`src/lib/chat/projectContext.ts:51-73`).
- **Shared pure sanitizers on both sides of the wire.** `sanitizeHistory` (`src/lib/chat/history.ts:17-30`) runs on client and server; `parseAttachments` strictly validates PNG prefix, ~1.5MB decoded cap, ≤4 items (`src/lib/chat/attachments.ts:17-32`) with a client mirror (`attachmentOversized`, :38-41) so oversize is refused loudly client-side (`src/components/live/PdfViewer.tsx:233`).
- **Fallback trigger is broader than the docs say — in a good way.** OpenAI fallback fires on fetch exception, any non-2xx, or a missing body, not just 503 (`route.ts:265-284`), and Gemini's first-turn-must-be-user constraint is normalized (`route.ts:230-231`).
- **`streamChat` throws `ApiError` with status so an expired session (401) is distinguishable from model failure** (`src/lib/api/chat.ts:98-111`).

### Must fix first

- **[BLOCKER] Mid-stream provider failure is converted into a clean stream end, so partial answers persist as complete.** The server catches the Gemini reader error, logs, and `controller.close()`s (`route.ts:321-325`); the client's stream resolves normally, `streamFinished = true`, and ChatView persists the partial text with `truncated: false` explicitly (`ChatView.tsx:238-243`). The client's entire truncation machinery (`errorKind: 'truncated'`, `ChatView.tsx:265`) is *unreachable* for a server-side mid-stream break — it only fires if the browser↔server connection itself dies. Same bug in the OpenAI fallback stream (`route.ts:93-95`). Stored conversations — which the smart layer's memory/retrieval will consume — contain silently amputated answers marked complete.
- **[BLOCKER] The empty-stream sentinel is a success-shaped error, and it gets persisted as a real answer.** When Gemini 200s but yields no text (safety block, immediate stream error) or the fallback stream dies before emitting, the server streams `'לא הצלחתי להפיק תשובה לשאלה הזו.'` as ordinary 200 body text (`route.ts:96, 324`). The client renders it as assistant content and saves it to the conversation; it is indistinguishable from the model actually saying it, and it is Hebrew regardless of locale. This is in-band error signaling — the exact fabricated-state class `rules/app.md` bans — and it poisons stored history.
- **[MAJOR] Missing `GEMINI_API_KEY` returns 200 with an English config message and never tries OpenAI** (`route.ts:146-148`) — success-shaped, persisted as an answer, and the OpenAI fallback is skipped even when `OPENAI_API_KEY` exists. Directly adjacent to the known "lead with OpenAI never reached this route" finding: provider order is hardcoded Gemini-first at `route.ts:23-26, 248`.
- **[MAJOR] The 40,000-char cut is silent, positional, and self-contradicting.** `buildText` keeps the transcript's *start* and slices at 40,000 UTF-16 units mid-word/mid-line with no marker (`src/lib/chat/context.ts:14, 22`); no flag reaches the route, header, model, or user. On a long call the Q&A tail is what gets dropped, and the system prompt then instructs "If the answer is not in the transcript, say so plainly" (`route.ts:214`) — so questions about the cut tail get a confident false "not in the transcript". `liveContext` gets the same silent `slice(0, 40_000)` (`route.ts:151`).
- **[MAJOR] `getChatContext` discards DB errors, making a database failure identical to "no transcripts exist".** `const { data } = await q` ignores `error` (`context.ts:35`, same in `byId` :42-46) → returns `{text:'', source:null}` → system prompt says "(No transcript context is available.)" (`route.ts:227`) → the model answers ungrounded with no signal anywhere.
- **[MAJOR] Zero prompt-injection posture: all untrusted content is concatenated into the SYSTEM prompt unfenced.** Transcript lines, client-supplied `liveContext`, project sources, and PDF page text join the system prompt with only `===` headings (`route.ts:221-227`); `liveContext` is *arbitrary client text placed in the system role* (`route.ts:150-151`). Workspace chat already solved this — `<<<ATLAS-SOURCE>>>` fencing plus fake-fence stripping (`src/lib/workspace/chat/context.ts:156`, `plan.ts:340`, `plan.test.ts:167-170`, `prompt.ts:104`). Low blast radius while the route is single-shot with no tools; lethal if the tool-calling smart layer inherits the pattern.
- **[MAJOR] A failed REPORT CONTEXT load is swallowed: `.catch(() => '')`** (`route.ts:174`) — the marked-passage grounding silently disappears while the snip chips still render as if grounded; no header, unlike `x-project-context`.
- **[MINOR] `x-chat-fallback: 'openai'` is set (`route.ts:101`) but no client reads it** — fallback usage is invisible to user and UI.
- **[MINOR] `message` is not type-checked** (`route.ts:120`, `if (!message)` at :144 passes any truthy non-string) and neither message nor history content lengths are capped.
- **[MINOR] Bearer-authenticated callers can never get project context:** the project client is built from cookies only (`route.ts:187`), so RLS returns nothing and `projectContext` reads `'failed'`.
- **[MINOR] A stale/deleted `transcriptId` with no `companyId` silently falls through to *any* latest transcript** (`context.ts:55-57`) — grounding on an unrelated company's call; `x-chat-source` does disclose the actual source.
- **[MINOR] The global `/chat` fallback query filters only `status='completed'`** (`context.ts:28-34`), so the 30 legacy Timlul personal-transcription rows in the shared table are eligible grounding for "broad market" chat.
- **[MINOR] Only `attachments[0].documentId` gets page-text grounding** (`route.ts:157-168`) — snips from a second document ship as images with no accompanying page text.

### Constraints on the rewrite

- **One wire client.** `streamChat` (`src/lib/api/chat.ts:92`) is the *only* `fetch('/api/chat')` in the repo (verified by grep). Exactly two components call it: `ChatView.tsx:191` (global Chat page, company chat, project chat) and `TranscriptChatPanel.tsx:154` (Ask Atlas on live calls and transcript/multiview pages).
- **Response contract on 200:** plain UTF-8 *text* token stream — no SSE framing, no JSON envelope — with `content-type: text/plain; charset=utf-8` and `cache-control: no-store` (`route.ts:30-39`); the client decodes raw chunks as deltas (`api/chat.ts:127-134`). Headers: `x-chat-source` = `encodeURIComponent(JSON.stringify({company, quarter, transcriptId}))`, empty string when no source (`route.ts:237, 330`); `x-project-context` ∈ `{'truncated','failed'}`, **absent means whole** — any new status value is silently coerced to null by the client whitelist (`api/chat.ts:52-54, 120`) unless the client is updated in the same change.
- **Response contract on failure:** non-2xx with JSON `{error}`; 401 must stay a distinguishable status because clients route it differently from model failure (`api/chat.ts:98-111`).
- **Request contract (`ChatInput`, `api/chat.ts:21-33`):** `message`, `companyId?`, `transcriptId?`, `liveContext?`, `documentRef?{documentId,pages}`, `attachments?` (≤4 PNG data URLs), `projectId?`, `history?[{role,content}]`. Clients send the *full* thread; the server owns windowing (currently `slice(-8)` + leading-assistant trim, `route.ts:230-231`).
- **Persistence semantics:** ChatView stores threads with per-message `projectContext` and `truncated` fields; stored jsonb *predates* both, so on read **absent must mean complete, never "unknown, warn"** (`api/chat.ts:52-66`, `ChatView.tsx:297-304`). A rewrite emitting richer degradation status must keep that backward compatibility or migrate the blobs.
- **The shared-corpus authorization stance is a founder ruling, not an oversight.** The rewrite must not "harden" transcript access into per-user scoping. Conversely, transcript **writes** still depend on `user_id` — retrieval design must not drop that column.
- **The auth boundary test will scan the new route** and requires a resolve+refusal pair per exported handler; it cannot verify auth-before-expensive-work ordering — the rewrite must preserve that by construction.
- **Errors must move out-of-band.** Today's clients render whatever streams (`TranscriptChatPanel.tsx:172` even renders `err.message` as content). Any in-band server text is indistinguishable from an answer — the rewrite must carry error/degradation state in status/headers/framing and update both callers in the same change.
- **Provider fact if Gemini is kept:** `thinkingConfig: { thinkingBudget: 0 }` is load-bearing (`route.ts:256-260`).
- **Snip ordering parity:** workspace's `askModel.ts:157` deliberately mirrors the image/caption ordering `/api/chat` sends — changing the ordering here breaks that cross-surface consistency.

## Slice 2 — `POST /api/workspaces/[id]/chat` (the strong backend, the retrieval seam)

### Sound to build on

- **Auth/authz is the strong pattern, end to end.** User resolved via `resolveUser` → `auth.getUser()` at `src/lib/auth/verifyUser.ts:26`, called at `src/app/api/workspaces/[id]/chat/route.ts:47-49`. Ownership is RLS-load-bearing, not app-filtered: the route queries `workspaces`/`workspace_items` through the user's cookie client (`route.ts:71-84`), and `loadItemContent` binds `itemId` + `workspaceId` through the same client (`src/lib/workspace/content.ts:53-58`). No `supabaseAdmin` anywhere on this path. Policies are the correct shape on all four workspace tables (`supabase/migrations/20260803_016_workspaces.sql:218-233`). **This is the pattern the smart layer should copy verbatim.**
- **The honesty machinery is real and closed on every content-dropping path found.** `truncated[]` covers both fewer-windows and trimmed-single-window cases (`src/lib/workspace/chat/plan.ts:316-323`), `omitted[]` covers zero-window files (`plan.ts:312-314`), the route merges both into `partial` plus `unreadable` for load failures (`route.ts:106-127, 205-206`), and the client renders them under the answer with per-title `<bdi>` (`src/components/workspace/WorkspaceChat.tsx:286, 456-474`). Trimmed windows are labeled in the prompt itself (`plan.ts:288`), dropped history turns are announced to the model (`route.ts:161-173`).
- **Hedging in `askModel` is correct.** `firstUsable` deliberately avoids `Promise.race` so a fast empty failure can't beat a slow good answer (`src/lib/workspace/askModel.ts:122-138`); the loser is aborted (`askModel.ts:84-98`); both providers failing yields `''` → `parseChatAnswer` null → the route returns `reply: null` and the client renders an explicit "could not answer" line, never success UI (`route.ts:188-196`, `prompt.ts:175-184`, `WorkspaceChat.tsx:280-289`). JSON parse is robust (`src/lib/workspace/intake/json.ts:61-89`) and a parse failure lands on the same visible no-answer path.
- **The budget arithmetic cannot drop the question** (caps verified: question ≤4,000 chars `route.ts:224`, selection ≤4,000 `route.ts:234`, ≤4 attachments ⇒ history budget ≥ worst-case question cost). Fragile-by-coincidence (nothing asserts it), but currently sound.
- **The seam already serves two callers** — chat (`route.ts:152`) and compose (`src/app/api/workspaces/[id]/compose/route.ts:133`) share `planContext`/`splitBudget`/`askModel`; `plan.ts` has a real unit-test suite.

### Must fix first

- **[BLOCKER] Untrusted titles and labels sit on the fence line, undefanged.** `defang` is applied only to window *body* text (`plan.ts:331, 340-341`; `context.ts:158`). `source.title` goes raw into the fence header (`plan.ts:328`), the outline (`plan.ts:227`), the shelf list (`prompt.ts:61`), and image captions (`attachments.ts:44-46`); window labels — lines *from the document itself* (`plan.ts:99-111`) — go raw into `[${w.label}]` at `plan.ts:331`. Titles come from `company_documents.title` / MAYA (third-party). A corpus document titled `X >>> <<<ATLAS-SOURCE …` forges a fence boundary and places instruction-position text outside the "quoted material" framing (`prompt.ts:104-110`). Bounded today (no tools); must be fixed before this prompt shape is generalized to a tool-calling model.
- **[MAJOR] The fairness pass spends budget on score-zero files and there is no query rewriting — together these are the mechanism behind "unable to pull required documents."** First pass takes one window from *every* file with no score threshold (`plan.ts:243-251`), each rationed an equal share (`plan.ts:256-267`): a 10-file shelf spends ~9 windows on the openings of irrelevant files before the relevant file gets a second window. Terms come from the last message only (`route.ts:144`, `plan.ts:220`), so a follow-up like "ומה לגבי השנה שעברה?" scores ~everything 0 and retrieval degenerates to "first window of each file" (tie-break `plan.ts:238`). Compounding: the `length > 2` filter drops "3"/"Q3" (`plan.ts:157`), and prefix-stripping removes only ONE letter, so "וההכנסות" never matches "הכנסות" (`plan.ts:162-167`, substring match `plan.ts:176`). Query construction (history-aware rewriting) and selection policy (score thresholds / relevance-weighted fairness) are part of the retrieval design — embeddings alone don't fix this.
- **[MAJOR] Thread storage is last-writer-wins with no version token, and the server never writes turns.** PUT replaces the whole jsonb array (`src/app/api/workspaces/[id]/thread/route.ts:56-92`; `workspaces.ts:448-465`); the "single writer" premise holds only per-tab (client serializes saves via a promise chain, `WorkspaceChat.tsx:211-220`). Two tabs/devices silently clobber each other, and any server-side writer (an agent appending its own turns) races the client's whole-array PUT and loses or destroys work. The smart layer needs append-per-message rows or a compare-and-swap version column before any server-authored turn exists.
- **[MAJOR] Every chat turn loads the full text of every shelf item from Postgres** (`route.ts:106-127`), including word-timed audio structures the planner never reads (`content.ts:122-131` vs `context.ts:74-90`). Load-everything-then-rank is the exact shape vector retrieval exists to delete, and a per-turn latency/DB cost the smart layer would multiply across agents.
- **[MINOR] `buildContext` in `context.ts` is dead code (used only by its own test) still carrying the "this is the seam" comment** (`context.ts:19-22, 100-133`). Two modules claim to be the swap-point; a designer reading `context.ts` first generalizes the wrong one. Delete or mark superseded.
- **[MINOR] `FENCE`/`defang` are duplicated** in `plan.ts:340-341` and `context.ts:156-158`.
- **[MINOR] The outline is charged against the budget but never truncated to it** (`plan.ts:224-232, 253, 334-335`).
- **[MINOR] Turns beyond `MAX_TURNS=24` are sliced silently** (`route.ts:226`) — `history.dropped` counts only budget drops.
- **[MINOR] The hedge's timeout starts when each provider starts** (`askModel.ts:110-113`), so Gemini launched at 6s can run to ~31s; nothing bounds the request overall.
- **[MINOR] The marked-selection block is untrusted document text placed outside the ATLAS-SOURCE framing** (`prompt.ts:74-81`) — analyst-chosen, low risk today; the fence rule should cover it when tools arrive.

### The seam verdict

**Real at the function level; aspirational as a description of the vector-retrieval work.** The boundary is exactly two pure functions — `terms()` (`plan.ts:150-169`) and `scoreWindow()` (`plan.ts:172-178`) — consumed at two call sites inside `planContext` (`plan.ts:220, 236`). Downstream uses only the *relative ordering* of scores (`plan.ts:238`); fairness, ration, trimming, and truncated/omitted accounting never touch term data. A cosine-similarity score genuinely drops in ordinally. What the claim hides:

1. **The architecture around the seam is load-everything-then-rank.** Embedding similarity at this seam means either embedding every window of every file on every turn (an API call inside a deliberately zero-model-call planner — `plan.ts:33-35`), or precomputed vectors — which need **stable chunk identities and a persistence layer that do not exist**: `windowsOf` yields positional indices and labels that shift whenever text or the `target` size changes, and nothing persists windows anywhere. The real smart-layer work (chunk table, embedding pipeline, index, retrieval that *avoids* loading the whole shelf) is entirely outside the "swap step 2" boundary.
2. **`planContext` is synchronous** (`plan.ts:209`); any embedding scorer makes it async — mechanically small, but "everything either side stays" is not literally true.
3. **Selection policy is not scoring** — the score-zero fairness spend and absent query rewriting live on the *keep* side of the seam and are part of why retrieval fails today.

Net: generalize this seam's *contract* (windows in, ranked selection out, truncated/omitted honesty preserved). But the architecture ticket should scope "vectors" as a new retrieval subsystem (chunk identity + storage + async planner + selection policy), not a one-function swap.

## Slice 3 — Storage, auth primitives, RLS posture

### Sound to build on

- **projects.ts and workspaces.ts are genuinely RLS-load-bearing.** Every exported function takes the caller's own supabase client, never `supabaseAdmin` (`src/lib/db/projects.ts:21-23,29-161`; `src/lib/db/workspaces.ts:30-569`). Zero-rows-matched is surfaced as `RowNotFound` → 404 (`workspaces.ts:143-147`), so "not yours" and "never existed" are indistinguishable to a caller.
- **Migrations 015 and 016 satisfy all four db.md ownership points**: real FK to `auth.users` ON DELETE CASCADE, RLS enabled, owner policy both sides `to authenticated`, index on `user_id` (`20260802_015_projects.sql:18-87`; `20260803_016_workspaces.sql:19-247`). Both add the composite `(id, user_id)` unique + composite child FK because Postgres RI checks bypass RLS (`016:96-108`, `015:116-122`).
- **20260801_014 is the correct shared-read shape**: `for select to authenticated using (true)` only (`20260801_014:43-47`). Same correct shape on `company_documents` / `document_pages` (`20260714_012:31-40`).
- **The supabaseAdmin-over-personal-rows modules owner-filter on every exported read AND write** for their own rows: `conversations.ts` (:41, :64-65, :100, :141-142, :160-162); `quotes.ts` (:70, :87, :121, :148-149, :189, :202, :210-211); `quoteFolders.ts` (:37, :54, :65-66, :75). One exception, flagged below.
- **The verified 2026-08-12 posture still holds** (6/6 supabaseAdmin importers in `src/lib/db` confirmed by grep).
- **Auth primitives are clean.** `getRequestUserId` validates bearer tokens via `supabaseAdmin.auth.getUser(token)` and cookies via `resolveUser`, which calls only `getUser()` and returns null on any failure (`src/lib/auth.ts:30-44`; `src/lib/auth/verifyUser.ts:22-32`). No live `getSession()` anywhere in `src`. `apiAuthBoundary.test.ts` structurally scans every handler and caps the PUBLIC allowlist at 8 with per-entry reasons.
- **Shared-corpus reads already work through the user's client** where the new pattern is used (`src/lib/workspace/content.ts:19-25`, `src/lib/workspace/intake/corpus.ts:9-44`, `workspaces.ts:476-521`).
- **chat_conversations has RLS + an owner policy despite its missing FK** (`20260613_009:25-31`), so `countProjectChats` through the user client is properly scoped.
- **transcripts main PUT is owner-or-admin gated in app code** (`src/app/api/transcripts/[id]/route.ts:94-108`); DELETE and PATCH admin-only (:127-134). For the corpus rows with `user_id IS NULL`, owner-equality fails and only admin can write — the right default.

### Must fix first

- **[MAJOR] Any signed-in user can rewrite speaker attribution on ANY transcript.** `renameSpeaker` and `saveSpeakerEdits` update `transcripts` by id with `supabaseAdmin` and no owner/admin check (`src/lib/db/transcripts.ts:7-35`), and their routes check only that *a* user exists (`src/app/api/transcripts/[id]/speakers/route.ts:10-20`, `src/app/api/transcripts/[id]/diarization/route.ts:15-51`). Incoherent with the same row's PUT (owner-or-admin): user B, forbidden from PUT on A's transcript, can still re-diarize the entire call via PATCH /diarization. Either these are corpus-curation writes (→ admin gate) or personal writes (→ owner check) — **a founder decision, now ticket 12** — before the smart layer copies either route as a template.
- **[MAJOR] `renameSpeakerInQuotes` writes into OTHER users' personal rows with attacker-chosen input.** It updates `quotes` filtered only by `transcript_id` + `speaker` — no `user_id` (`src/lib/db/quotes.ts:166-184`) — reachable by any authenticated user through the speakers route with arbitrary `oldName`/`newName` (`speakers/route.ts:17,20` → `transcripts.ts:24`). Every user's saved quotes on that transcript get their `speaker` field rewritten.
- **[MINOR] `chat_conversations_owner` policy omits `to authenticated`** (`20260613_009:30-31`), so it is granted to `public`. Not exploitable, but a deviation from the convention — don't let it be the copy source.
- **[MINOR] `renameSpeaker` is a read-modify-write on the `speaker_names` map with no concurrency control** (`transcripts.ts:13-22`); two concurrent renames lose one edit.
- **[MINOR] GET /api/transcripts/[id] logs the full row (`JSON.stringify(rows)`) on every request** (`[id]/route.ts:70-72`) — entire transcript bodies into Railway logs.

### Facts for the embeddings/agents tables design

- **`document_embeddings` conflicts with nothing.** The shared-corpus posture is live and consistent: no `user_id`, writes via service role only, one `for select to authenticated using (true)` policy — copy `20260714_012:31-40` / `20260801_014:43-47` verbatim. The banned shape is `FOR ALL` + `WITH CHECK (true)` + role `public` (two live linter-flagged examples exist — `profiles`/`access_requests` — do not imitate, do not "fix" without checking Timlul).
- **Personal tables (agents, agent_runs, memory) must copy migration 015/016, not the five FK-less tables.** Full template: FK to `auth.users`, RLS, owner policy both sides `to authenticated`, `user_id` index, PLUS `unique (id, user_id)` on the parent and a composite `(parent_id, user_id)` FK on every child (`20260803_016:96-108`). `chat_conversations` can never gain an FK (7 orphaned-owner rows, `20260802_015:126-128`) — agents must not reuse it; 016 already refused to (`016:128-133`).
- **Client choice for new tables: user client + RLS (projects/workspaces pattern), not supabaseAdmin + app filter.** `workspaces.ts:24-26` says explicitly the older modules "are not the pattern here" — and the two speaker-edit defects are exactly what the admin-client pattern permits. If an agent runner must use the service role (background jobs with no request cookie), every query needs the explicit owner filter and that fact stated per module, per app.md's RLS law.
- **`transcripts.id` is TEXT, not uuid** (`20260803_016:46-50`). An embeddings table keyed by transcript needs a text FK.
- **Whole-jsonb message threads don't fit agent runs.** `workspace_threads.messages` is replaced wholesale on every `patchThread` (`workspaces.ts:448-465`) — unbounded row growth, last-write-wins, cascade destroys the whole history with the row. Agent runs / memory want append-only child rows.
- **PostgREST silently caps at ~1000 rows and returns a short list, not an error** — `listCalls` already paginates for this (`src/lib/db/calls.ts:84-125`). Any retrieval path over an embeddings table must bound or page its reads.
- **New API routes**: the copyable primitive is `getRequestUserId` + `unauthorized()`; the boundary test will scan them; the anonymous surface is capped at 8. The one thing the test does NOT check is post-auth *authorization* — the speakers/diarization routes passed it while missing the ownership check, which is precisely the gap an agents route could reproduce.
- **Delete paths owe a count-before-destroy** (`countProjectChats`, `countWorkspaceContents` — `projects.ts:138-145`, `workspaces.ts:552-569`); agent runs stored under a cascading parent inherit it.

## Slice 4 — Citation-anchor machinery

### Sound to inherit as the standard

- **The anchor quartet as a DB shape is real and well-constrained.** `20260803_016_workspaces.sql:156-199` stores `source_item_id + source_label + source_page/source_line_id + source_quote`; `workspace_doc_blocks_quote_has_text` (016:178-179) makes a quote without its snapshot unrepresentable, mirrored client-side at `src/lib/workspace/validate.ts:240-242`.
- **The broken-source state survives by construction.** `ON DELETE SET NULL (source_item_id)` (016:196-199, tightened to a workspace-scoped composite FK at `20260803_017_workspace_integrity.sql:67-71`) releases the anchor while `source_label`/`source_quote` survive as readable evidence.
- **The "missing" render state is fully implemented end-to-end:** `blocksToHtml` marks orphans `data-citation="missing"` (`src/lib/workspace/blocks.ts:307-311`), `domToBlocks` reads that back as a quote so autosave cannot destroy the evidence (`blocks.ts:173-186`), CSS strikes the cite line with a localized reason (`src/app/globals.css:869-881`, `WorkingDocument.tsx:351-357`), and removal warns with the citation count first (`present.ts:139-148`, `WorkspaceShell.tsx:1686`).
- **Cross-workspace and cross-user citation is impossible in the database** (017:57-71 binds `(source_item_id, workspace_id, user_id)`; 016:93-108).
- **The citation is immutable after creation by API contract:** `parseBlockPatch` accepts only `body`/`position` (`validate.ts:266-291`); a kind change is deliberately delete+create so a de-quoted paragraph loses its anchor rather than wearing it falsely (`blocks.ts:224-259`).
- **Serving the source fresh is understood:** the content route is `no-store` because `formatted_data` is regenerated (`src/app/api/workspaces/[id]/items/[itemId]/content/route.ts:12-19`).
- **Anchor capture is honest at the UI layer:** line id read from the actual DOM node the selection starts in (`SourceDocument.tsx:273-285`); "Quote it" stores the analyst's verbatim selection with no model call (`WorkspaceShell.tsx:641-652`).

### Must fix first

- **[BLOCKER] No write-time verification of any anchor against the source.** `POST /blocks` → `parseBlockCreate` → `addBlock` (`blocks/route.ts:16-21`, `validate.ts:223-264`, `workspaces.ts:362-387`) validates only shape. Nothing checks `source_quote ⊆ source text`, that `source_line_id` names an existing line, or that `source_page ≤ page_count`. A writer (today: a human's own selection; in the smart layer: a model) can write a claim anchored to a nonexistent L0099 and it renders as an intact, live citation. **The machinery can fully represent a lie at write time.**
- **[BLOCKER] Drift detection is designed, unit-tested, and wired to nothing.** `citationState()` (`present.ts:33-41`) implements live/drifted/absent and is called only by its own test; no component resolves an anchor against the current source. `blocks.ts:271-286` states this openly. Since `formatted_data` is regenerated on re-processing, a re-processed call currently renders drifted quotes as normal live citations — the exact failure the snapshot column exists to prevent.
- **[MAJOR] A live-cited quote's visible words are editable away from its snapshot.** `parseBlockPatch` allows `body` on a quote block (`validate.ts:274-291`), the rendered text is `body` not `source_quote` (`blocks.ts:313`), and nothing ever compares them. An edited quote still renders with an intact citation.
- **[MAJOR] Line ids are positional, not stable.** The sole mint is `src/lib/transcription.ts:503-512`: `L${counter}` assigned by paragraph order over Gemini's nondeterministic markdown output, plus a wholesale renumbering path in the Q&A fallback (`transcription.ts:528-530`). "Stable id" today means "stable within one `formatted_data` generation." Re-processing renumbers everything, so `source_line_id` is a snapshot coordinate, not a durable identifier — drift detection is the only thing that could make that safe, and it doesn't run.
- **[MINOR] The "one anchor" constraint is at-most-one, not XOR** (`num_nonnulls(source_page, source_line_id) <= 1`, 016:176-177): a cited quote with neither anchor is legal, and nothing ties anchor type to the cited item's kind.
- **[MINOR] The visibly-broken guarantee hangs on `source_label` presence, a convention.** Orphan detection is `!source_item_id && Boolean(source_label)` (`blocks.ts:307`); the DB permits `source_item_id` with NULL label (`validate.ts:258-259`). Such a block, on source deletion, renders unmarked and the next autosave destroys `source_quote`. Unreachable via the current UI, open via the API.
- **[MINOR] Two vocabularies for one state:** `data-citation="missing"` in DOM/CSS vs `CitationState 'absent'` (`data.ts:192`); `blocks.ts:283-286` flags present.ts as the one to extend.

### Gaps between shipped anchors and the citations law

- **The minute does not exist in this machinery.** The founding law wants call · minute · line; the anchor has no timestamp column (016:156-169), the Gemini pipeline hardcodes every line's timestamp to `'00:00:00'` (`transcription.ts:507`), and the transcript citation label is just `${company} — ${quarter}` (`content.ts:138`) — the migration's own example label with `· 00:12:31` is aspirational. Real per-word timings exist only for IVRIT-pipeline calls (`word_segments`, 4/56 transcripts per `contentTypes.ts:35-40`) and are never joined to L-ids. The smart layer must either add a timestamp to the anchor or make line→time resolvable, and must fix the pipeline to emit real line timestamps.
- **Anchors are display-only; there is no resolution primitive.** An intact citation is not clickable and no code path resolves an anchor to its current source text. The pieces exist (`loadItemContent` serves lines with ids and pages with text, `content.ts:142-155, 170-179`) but nothing composes them with `citationState`.
- **No server-side citation writer exists to inherit.** Today's only citation producer is human selection in the browser; Atlas's own compose path writes blocks with no citation at all (`compose/route.ts` — zero matches for `source_`/`citation`). The smart layer's claims will be model-generated, so the verify-at-write choke point (M3) must be built new — the current write path was designed for a trusted human and merely shape-checked.
- **Scope note:** the quartet anchors to a *workspace item* (personal layer), not the corpus row (`source_item_id` → `workspace_items` → `transcript_id`/`document_id`, 016:72-108). A corpus-grounded citation standard needs an anchor that points at `transcripts`/`company_documents` directly, or it inherits the item indirection — and that `SET NULL` conflates "user tidied their shelf" with "source ceased to exist," correct for a personal document and wrong for a corpus-grounded claim.

**Slice verdict:** the quartet *shape* (id + label snapshot + position + quote snapshot) and the visibly-broken-never-silently-wrong philosophy are worth inheriting — they are the best-constrained tables in the repo. But the machinery verifies nothing at write time, detects nothing at read time, and its line ids and labels cannot express the founding law's coordinates. Inherit the schema pattern; do not inherit the assumption that the writer is honest.
